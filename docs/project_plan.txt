### 5.2 Classical crypto (`crypto/classical.py`)

Use `cryptography` library. [ppl-ai-file-upload.s3.amazonaws](https://ppl-ai-file-upload.s3.amazonaws.com/web/direct-files/collection_a17ea0e5-9409-4977-ab7e-704165006225/4ce23845-2a68-447d-9255-4bcd96dcd2d2/PQC-Banking-API-Implementation.pdf)

Functions:

1) `generate_rsa_keypair()` – RSA‑2048 key pair.  
2) `derive_session_key_rsa()` – simple approach:  
   - Generate random 32‑byte AES key.  
   - Encrypt it with RSA public key (PKCS1v1.5 or OAEP for better practice).  
   - For MVP encryption of transactions we can skip sending encrypted key back; we only need to measure encryption metrics locally.  

3) `encrypt_transaction(plaintext: bytes) -> (ciphertext, iv, tag, metadata)`  
   - Generate random 32‑byte AES key.  
   - Generate 12‑byte IV.  
   - AES‑GCM encrypt.  
   - Metadata includes:  
     - `"asym": "RSA-2048"`  
     - `"sym": "AES-256-GCM"`  
     - key sizes: 2048 bits, 32 bytes. [ppl-ai-file-upload.s3.amazonaws](https://ppl-ai-file-upload.s3.amazonaws.com/web/direct-files/collection_a17ea0e5-9409-4977-ab7e-704165006225/4ce23845-2a68-447d-9255-4bcd96dcd2d2/PQC-Banking-API-Implementation.pdf)

4) `decrypt_transaction(ciphertext, iv, tag, metadata)` – for completeness, even if you don’t show it in demo.

### 5.3 PQC crypto via liboqs (`crypto/pqc.py`)

Following your blueprint: ML‑KEM for key establishment + AES‑GCM for data. [ppl-ai-file-upload.s3.amazonaws](https://ppl-ai-file-upload.s3.amazonaws.com/web/direct-files/collection_a17ea0e5-9409-4977-ab7e-704165006225/f16ff03b-e1da-491d-a95a-ee4d5111489b/I-have-not-done-any-implementation-of-this-project.pdf)

Assuming Python binding exposes an API similar to liboqs:

Functions:

1) `generate_kem_keypair()` – use ML‑KEM‑768:  
   - `kem = oqs.KEM("ML-KEM-768")` (or similar).  
   - `public_key, secret_key = kem.generate_keypair()`.

2) `encapsulate(public_key)` – returns `(ciphertext, shared_secret)`.

3) `decapsulate(ciphertext, secret_key)` – returns `shared_secret`.

4) `derive_session_key(shared_secret)` – use HKDF or a simple KDF to derive 32‑byte AES key.

5) `encrypt_transaction_pqc(plaintext: bytes) -> (ciphertext, iv, tag, metadata)`  
   - Generate ML‑KEM shared secret; derive AES key.  
   - AES‑GCM encrypt.  
   - Metadata includes:  
     - `"kem": "ML-KEM-768"`  
     - `"sym": "AES-256-GCM"`  
     - public key and ciphertext sizes (obtain from kem or from len(public_key), len(ciphertext)). [ppl-ai-file-upload.s3.amazonaws](https://ppl-ai-file-upload.s3.amazonaws.com/web/direct-files/collection_a17ea0e5-9409-4977-ab7e-704165006225/5751c9a8-ece1-47a5-9a31-d8dbee125dbe/Project_Sections_3-1-3-6.md)

## 6. Metrics service (`services/metrics_service.py`)

Implements aggregation for dashboard. [ppl-ai-file-upload.s3.amazonaws](https://ppl-ai-file-upload.s3.amazonaws.com/web/direct-files/collection_a17ea0e5-9409-4977-ab7e-704165006225/f16ff03b-e1da-491d-a95a-ee4d5111489b/I-have-not-done-any-implementation-of-this-project.pdf)

Function:

- `get_current_metrics(session, window_seconds=60)`:

  1) Compute cutoff time `now - window_seconds`.  
  2) Query `Transaction` rows with `created_at >= cutoff`.  
  3) Partition into two lists: classical vs pqc.  
  4) For each mode compute:  
     - `count`.  
     - average `latency_ms`.  
     - average `ciphertext_size`.  
  5) Return dict:

```python
{
  "window_seconds": window_seconds,
  "classical": { "count": ..., "avg_latency_ms": ..., "avg_ciphertext_size": ... },
  "pqc": { "count": ..., "avg_latency_ms": ..., "avg_ciphertext_size": ... }
}
```

Agents must ensure this is JSON serializable.

## 7. API routes

### 7.1 Transaction encryption route (`routes/transactions.py`)

Endpoint: `POST /api/transaction`. [ppl-ai-file-upload.s3.amazonaws](https://ppl-ai-file-upload.s3.amazonaws.com/web/direct-files/collection_a17ea0e5-9409-4977-ab7e-704165006225/5751c9a8-ece1-47a5-9a31-d8dbee125dbe/Project_Sections_3-1-3-6.md)

Request JSON:

```json
{
  "mode": "classical" | "pqc",
  "transaction": {
    "from_account": "123",
    "to_account": "456",
    "amount": 1000.0,
    "currency": "INR"
  }
}
```

Implementation steps:

1) Validate `mode`.  
2) Serialize `transaction` dict to bytes (e.g., `json.dumps(...).encode("utf-8")`).  
3) Start high‑resolution timer.  
4) If mode = `"classical"`: call `encrypt_transaction`.  
   If mode = `"pqc"`: call `encrypt_transaction_pqc`.  
5) Stop timer; compute `latency_ms`.  
6) Build a `Transaction` ORM instance with all fields set, including `ciphertext_size = len(ciphertext)`.  
7) Commit to DB.  
8) Return JSON:

```json
{
  "id": "<id>",
  "mode": "pqc",
  "latency_ms": 7.9,
  "plaintext_size": 128,
  "ciphertext_size": 1200,
  "algorithm_info": { ... }
}
```

### 7.2 Metrics route (`routes/metrics.py`)

Endpoint: `GET /metrics`. [ppl-ai-file-upload.s3.amazonaws](https://ppl-ai-file-upload.s3.amazonaws.com/web/direct-files/collection_a17ea0e5-9409-4977-ab7e-704165006225/f16ff03b-e1da-491d-a95a-ee4d5111489b/I-have-not-done-any-implementation-of-this-project.pdf)

1) Read optional `window_seconds` query param, default 60.  
2) Get DB session, call `get_current_metrics`.  
3) Return metrics JSON.
